# ADR-006: Balanced AI harness

**Status:** Proposed record of approved baseline choice — confirm before marking Accepted.  
**Date:** 2026-11-11

## Decision
Main agent implements, independent read-only reviewer checks, human owner approves architecture/merges/production secrets.

## Context / tradeoff
Adopt the smallest maintainable architecture serving Amber Hunter MVP and portfolio goals. Verify versions, pricing, security and API limits during bootstrap. Further implementation details remain open.

## Consequences
Document any divergence and create a follow-up ADR rather than silently changing this baseline.

## Proposed clarification — Restricted Local Reviewer for MVP

The owner accepts the Restricted Local Reviewer operating model for MVP. This section proposes recording that decision in ADR-006. The ADR status above still applies.

The Reviewer inspects local diffs and supplied requirements and test evidence in a separate CLI session with an effective `read-only` sandbox and `never` approval policy. Authenticated GitHub access is outside the MVP review workflow. Main or the owner supplies any needed GitHub context and handles remote operations.

Remote write isolation remains unproven. The local controls do not establish the permissions of built-in services, browsers, or credentials available to the same OS user. A human must review security-sensitive changes before merge, including changes to credentials, permissions, sandbox policy, connectors, and deployment controls. The [Reviewer runbook](../harness/REVIEWER.md) records the verified controls and residual risks.
